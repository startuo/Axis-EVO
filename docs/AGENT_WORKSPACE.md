# M6 · Agent Engineering & Evidence

Axis-Evo **0.1.0 Preview** 默认使用 Chat 与 Work。选择工作区后直接描述目标，Agent 根据任务发现资料和 Skill，调用程序注册的工具，保存文档并继续修订。每次普通文件操作不再要求用户单独批准；操作范围来自用户预先设置的目录与读写策略。

## 启动

在项目根目录使用 Python 3.11+；Windows 执行要求普通 CPython，Microsoft Store/WindowsApps Python 不受支持，使用它创建的虚拟环境也不受支持。Windows 凭据管理需要可选 `web` 依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[web]"
.\.venv\Scripts\python.exe -m examples.agent_workspace --data-dir "$env:LOCALAPPDATA\AxisEvo\data" --open-browser
```

完整交付 ZIP 已包含 `web/dist`。源码检出需先在 `web` 目录执行 `npm ci`、`npm run build`（Node 22.12+）。服务器只监听 `127.0.0.1`，默认端口 8765，可用 `--port` 指定。`--api-only` 用于前端开发，`--web-root` 可指定构建目录。

首次打开设置中的「模型连接」配置模型，再添加工作区。工作材料目录与 Agent 状态目录必须分别存放，不能互为父子目录。知识库备份和 Skill 库在「知识与 Skills」中单独授权，只读接入；未连接的目录不会被自动搜索。撤销来源会阻止后续读取与 Skill 使用。

`--network-config` 可接收后端管理员配置的 `credentials` 环境变量引用、`endpoints`、`local_gateways` 和 `provider_routes`。它不接受明文密钥或研究项目配置。网络与模型协议说明见 [AGENT_PROVIDER.md](AGENT_PROVIDER.md)。此启动器不创建研究示例、任务模板或实验数据库。

## 日常协作

- **Chat**：描述目标、附加当前明确选择的 Edge 页面、查看交付物，继续同一会话修订。对话输入与已用 Skill 版本持久保留。
- **Work**：按工作区浏览任务和交付物。交付卡区分当前文件与已保留版本；可预览和下载对应的历史文本。
- **设置**：管理工作区读写范围、资料来源、模型、Skill 改进策略、内置工具、Edge 安装更新以及表达风格。
- **反馈**：说明结果是否有帮助；需要改进时可以补充必含文字、禁含文字或实际标题要求。反馈与本轮执行证据绑定。

20 个内置工具覆盖项目概览、任务计划、隔离命令、固定验证、文件差异，以及列目录、搜索、读取、写入、精确替换、Skill 发现与使用、Edge 正文及快照读取。写入已有文件必须使用已读取的 SHA-256，保存前后版本并独立核对实际字节。另有单层创建目录、单文件移动/删除和只读 Git 状态/历史/差异。工具目前处理 UTF-8 普通文本；创建目录的父目录仍需存在。宿主不运行项目 Shell；单独授权后可在无网络 Linux 容器副本中运行项目命令。单文件只读上限 4 MiB，单次返回最多 24,000 字符；写入仍限 128 KiB，工具参数另受 40 KiB 上限约束。目录扫描最多 2,000 项，单次搜索最多 8 MiB；超限、跳过或未读内容明确标注。

搜索结果包含路径、完整文件 SHA-256、实际行号和字符范围。`read_file` 可用 `startChar` / `maxChars` 按需续读，并用 `expectedSha256` 拒绝混用已变化的版本。`coverage=PARTIAL` 表示片段，不能据此声称整篇内容已核对。这里是有界文本搜索与读取，不是向量检索或任意规模文档研究。

Edge 扩展 **0.2.3 / 协议 2** 会报告自身版本，工作台提供当前目录、更新提示和重连状态。旧协议 2 扩展仍可连接，但显示需更新。重新连接不重放旧操作。Agent 原生工具可观察当前附加页面；有副作用的网页操作继续使用原有精确操作审批，高风险操作交由用户完成。安装步骤见设置的「工具与插件」。

连接状态查询在暂时失败后会继续轮询，恢复后只清除连接状态错误，保留操作失败与 UNKNOWN。移动项目目录后须核对 Edge 加载的扩展位置；旧目录的“重新加载”不会自动迁移到新目录。

## 项目命令与固定验证

在「设置 → 工具与插件」为当前工作区选择已安装的可信 Linux 镜像，并显式保存执行授权。默认关闭；无 Docker 时没有宿主执行回退。镜像不会自动下载，授权固定完整 `sha256:` ID。用于本轮验证的环境为 Docker Desktop Linux 引擎与官方 Python 3.12 slim；有依赖的项目需由用户预先准备包含依赖的可信镜像。

例如先由用户在终端准备镜像，再在界面选择它：

```powershell
docker pull python:3.12-slim
docker image inspect python:3.12-slim --format '{{.Id}}'
```

镜像需要提供 `/bin/sh`、`tar`、`env`、`timeout` 和 `chmod`；实际项目运行时另需语言运行环境。Windows 使用本机 Docker Desktop Linux named pipe，Linux 使用本机 Unix socket，不接受模型提供的远端 Docker 上下文。镜像声明自动挂载卷时拒绝执行。

- 命令只获得授权工作区的完整 UTF-8 文本副本：最多 2,000 项、总量 16 MiB；仅 `.gitignore`、`.gitattributes`、`.editorconfig`、`.prettierrc`、`.prettierrc.json`、`.eslintrc.json` 这些公开点文件例外；其他隐藏/凭据文件、链接、二进制、依赖目录和构建目录不会复制。清单与字节 SHA 一同记录；这不是整个 Git checkout 的等价复制。
- 命令容器无网络、无宿主目录/套接字挂载、非 root、只读根文件系统、无 capabilities、no-new-privileges，并限制内存、CPU、进程、临时空间和输出。每条命令最多 120 秒，工作区可设更低值；仅保留前 64 KiB 输出并标截断。
- `run_command` 允许修改容器内临时副本，但不写回项目。实际源码修改仍通过原 Core 写入与字节校验；多文件修改不是原子提交。`inspect_changes` 显示每个文件首次保存前与最后版本的差异。
- 固定验收命令和固定验收文件由设置 API 保存，模型和候选无修改入口。验证文件保存无 BOM 的 UTF-8 字节与 SHA，合计最多 256 KiB。Agent 写入这些路径会被拒绝。
- `run_checks` 和 Skill 比较使用只读项目输入。固定的可信解包器准备独立 Docker volume，随后非 root 命令容器只读挂载该 volume；没有宿主 bind mount。候选不能替换冻结文件来改变验收依据。运行时代码仍可能针对已知测试优化，已知开发检查不等于隐藏测试或通用正确性。
- 已确认的非零退出码表示命令失败，区别于工具派发未知。未知执行、权限撤销、时限或输出无法核对会阻止后续采用。授权版本变化停止正在执行的任务/比较，用户可创建新任务继续。
- 协调进程中断后，容器内部 `timeout` 仍会终止项目进程树；重启不会重新执行未知操作。进程崩溃可能留下已停止的容器/输入卷，目前没有自动清理崩溃遗留资源的后台机制。

这是实际 Linux 容器隔离，依赖可信 Docker daemon、镜像、宿主内核及 Docker Desktop 的 Linux VM；不是路径过滤沙箱，也不宣称防御内核/daemon 漏洞或同一 OS 用户。设计依据见 [Docker 安全边界](https://docs.docker.com/engine/security/)、[容器运行参数](https://docs.docker.com/reference/cli/docker/container/run/)、[tmpfs](https://docs.docker.com/engine/storage/tmpfs/) 和 [Windows 权限要求](https://docs.docker.com/desktop/setup/install/windows-permission-requirements/)。

「依据这次进展继续」将任务关联带入新一轮，并预填核对进展的目标，发送后才启动；它不自动重放旧调用，也不解除已有未知写入围栏。计划中的完成标记是模型声明，实际完成以保存字节、退出码和固定验证记录判断。

## 运行结构

产品层新增 `agent.sqlite3` 追加式记录、受控工作区服务、工具注册表及原生工具回路。每轮最多 32 次模型请求、96 次工具调用和 1,200 秒；模型请求使用有墙钟期限的独立进程，取消后迟到响应不得派发工具。Provider 配置版本和网络授权每次重新核对。

模型只提出工具请求。宿主验证工具名、参数、授权来源、目录身份与路径；网页和 Skill 文本不能增加权限。每轮固定来源授权集合；新增或撤销来源会停止当前轮，已发出的模型请求会被取消，迟到响应不得派发操作。文件写入复用原 Core 的安全打开、Tool Intent/Result、验证及 Run 事件，每次修改生成独立 Core 数据库，避免改写旧实验事实。产品持久层和文件记录并非完整 OS 沙箱，也不抵御同一 OS 用户主动修改所有运行状态。

派发意图先于实际操作保存。未经确认的写入会按规范物理路径阻止后续自动重试，包括大小写别名、重叠工作区和完整历史。服务重启把未完成任务保留为 UNKNOWN，不恢复模型请求或副作用。用户仍可继续其它目标；当前没有自动消除未知结果的机制。请求响应丢失时，界面用原请求标识查询事实，不自动新建重复请求。

`tool_execution` 在派发前关联 Agent intent 与 Core Run/目录、Edge operation 或准备好的容器身份；`tool_result.executionId` 指向该关联。写入后回执落盘失败仍为 UNKNOWN，不能由协调器错误改称明确拒绝。每次工具调用前都检查总时限。只读/Edge/容器等待不占用文件写入授权锁，停止与撤销可以及时被记录；迟到读取不进入下一次模型请求或文件写入。各组件保留独立事实库，不宣称跨 SQLite 与文件系统原子提交。

同会话保留至多 64 轮用户原文及反馈检查，合计预算 80 KiB；达到预算会明确要求新建对话，不静默丢弃旧要求。最近六轮回复仅保留带截断标记的摘要片段。模型请求上下文软目标为 48 KiB，硬上限仍为序列化后的 224 KiB；旧工具正文可压缩成有身份、状态和摘要的宿主回执，原文仍在日志，模型必须重新读取才可引用省略的来源。用户要求和已用 Skill 指令不由模型摘要改写。这是字节预算，不是供应商 token 上限的保证。

## Skill 改进

复用现有 `SkillManager`、不可变版本、DERIVED 来源链、修订草案协议及 Core 执行证据。产品 Skill 数据位于独立 `agent-skills.sqlite3`；导入版本是 CANDIDATE，修订版本是 SHADOW，指令不授予工具权限。

新反馈默认 `TASK_ONLY`，只保留本次任务偏好。用户明确选择“用于今后的同类任务”后记录为 `REUSABLE_PREFERENCE`，再按工作区策略触发一次周期；历史反馈和采用记录不重写。任务未确认完成或存在工具失败时，先保留反馈并暂停归因，不自动认定为 Skill 缺陷。

1. 从实际任务、固定 Skill 与反馈生成候选。
2. 可配置另一模型或同模型的独立上下文审查；相同 modelId 更换 endpoint 仍标同模型。不同配置名不认证底层模型或训练数据独立，审阅只作为建议。
3. 捕获已授权输入并恢复原任务写入前的版本，建立两个隔离工作区。使用同一任务、固定对话输入、模型配置与工具范围，分别实际执行原版和候选；不会重放原网页操作或写入原工作区。
4. 新比较使用 `agent-skill-product-gate-v3`，固定原任务交付文件集合。文档要求可指定原交付路径，未指定时应用于每份原交付文件；固定项目命令由宿主独立执行，使用用户冻结的验证文件。不能增加旁文件补足原报告，也不能把要求搬到另一文档掩盖退步。多次修订只以每个文件的最后版本判断，旧版本仍保留在证据中。
5. AUTO 只在全部要求通过、至少一项改善、没有退步、审查无反对/不确定结论且原授权仍有效时采用候选指令。OBSERVE 保留候选，OFF 只记录反馈。撤销授权或停止策略会中止后续评价与采用。

没有客观检查时不以模型认可代替验证。标题检查使用 Markdown ATX 标题的完整文字，不包含 `#`，编号须一致；代码块中的伪标题不算通过。例如“归档清单”不会匹配“六、归档清单”。采用记录仅表示 **明确文档或固定项目检查范围内** 的产品偏好版本，不宣称整体语义能力提升。该比较使用开发反馈，不能作为独立 Holdout 或论文实验。旧研究 Gate 要求其封存的评估条件，产品层不伪造旧 Gate/Assessment 或晋升为研究 TRUSTED。

读取与搜索片段的来源摘要均须与对照输入一致；来源变化时停止。包含网页材料的原任务目前不能复现完整网页输入，会明确停止对照，不能省略网页后声称公平比较。隔离副本总量限 2 MiB，超过完整读取范围也停止。历史原任务使用固定的 Provider 配置版本；配置中的临时网络路由已过期时，比较会停止，不擅自换新版本或改写原任务。

### 诊断、历史经验与采用策略

诊断区分仅本次偏好、长期改进假设、成功经验、工具/环境故障、未确认执行和不能归因的反馈。已在派发前明确拒绝的参数错误，若后来同一工具目标成功，可记为已纠正；原拒绝记录仍保留。UNKNOWN、实际失败及尝试修改固定验证文件不会因此消失。模型诊断不证明 Skill 是根因。

可复用反馈会冻结原任务写入前的材料、会话输入、反馈检查与执行策略；成功反馈也可保存为后续回归案例。最多保留 200 个有界开发案例，达到上限不自动删除旧证据；每次候选比较选至多 2 个去重的同 Skill 案例，优先一例负反馈、一例成功反馈，再补足；相同来源和检查不重复执行。主比较未达 Gate 时不继续花费历史回归请求。来源授权撤销、材料摘要损坏、执行策略变化或旧模型路由失效会停止比较。选择不是穷尽历史，也不是独立 Holdout。

单个演化周期有 64 次模型请求、900 秒预算，涵盖修订、审阅及所有比较任务。候选请求数不得超过 `max(4, 2×原版)`，工具数不得超过 `max(12, 2×原版)`，已观察命令时间不得超过 `max(10秒, 3×原版)`；超过则保留证据、不自动采用。这里统计执行成本，不推算账单。现场验收还受另行授权的更小调用总量约束。

当前可自动实施的是 Skill 指令/执行工作流修订，并组合冻结的样例、历史反例与固定代码验证。诊断可以建议工具或环境修复，但不能自行修改宿主工具实现、评价标准或权限。只要比较未完成，就不将缺失文档算成已测质量退步。普通符合全部证据要求的修订可按 AUTO 策略采用，不要求逐次人工审批。

界面支持回退到当前导入原版；API 还允许选择曾通过该来源评价并采用的版本。回退仅影响后续任务，追加选择记录，不覆盖旧版本、旧 Gate、已交付文件或采用事实。M6 在后续完成任务上检查已采用版本的固定文档要求。仅原始输入、对话、模型配置、Harness、固定执行策略全部一致且 AUTO 仍有效时，才可追加自动回退事实；条件变化只记录退化信号。范围仅为实际观察到的交付路径和字面条件，不是长期语义监测或通用代码回归。

## 工作树搬迁

工作树共享主项目的 `.git` 管理目录。手工移动目录后，可用 `git worktree repair "新工作树绝对路径"` 修复登记，再核对 `git worktree list`；无需合并到 `main` 即可构建、运行和提交该分支。虚拟环境或本地启动脚本可能仍引用旧路径，需要重建或修正。

代码路径与运行状态路径分别核对。若也移动 `--data-dir`，已有工作区授权、交付版本绝对路径及 Windows 凭据作用域需要单独处理；Git 路径修复不迁移运行数据库。正式产品统一使用 `main`。学术冻结保存在 `academic/thesis-freeze-2026-11-02`；旧 M5 工作树保留本地材料，M6 开发树保留本轮审查材料。使用短期功能分支，验证后快进回 `main`，不继续扩展多个长期产品主线。

## 当前边界与后续方向

MCP 与 DeepSeek Harness 的协议和架构已经审查；当前使用供应商无关的原生 function calling 与现有受控 Gateway。尚未实现任意 MCP 服务安装、远端工具权限注册或 Harness 联机集成。后续可在同一宿主授权和事实协议下增加适配器。

当前交付以文本文件为主；通用 Office 渲染、宿主终端/网络依赖安装、网页跨站自主操作、长期语义质量评价和未知副作用人工核销仍需后续工程。用户真实知识库尚未接入。实际模型、文件、UI 与离线边界测试分别记录在 [TEST_RESULTS.md](TEST_RESULTS.md)。学术研究基线保持 `12c789b187a6bf8332b8d5222d00cc0702d4bdc8`。

## M6 文件、Git 与执行环境

移动与删除仅允许单个不超过 128 KiB 的普通 UTF-8 文件，需要完整原字节 SHA。目标不得覆盖，删除前原件持久保留；移动是复制、验证、删除三个步骤，并非原子重命名。部分完成保持 UNKNOWN，源和目标都受后续写入围栏保护；目录不递归删除。固定验证路径及其祖先目录受保护，读写策略由宿主执行。CRLF 文件唯一替换兼容 LF 格式的模型参数，仍核对完整原 SHA，混合换行不自动归一化。

`git_status`、`git_log`（最近 8 条）、`git_diff`（单个可读文件相对 HEAD）均为只读，不执行 hooks、外部 diff、textconv 或 fsmonitor，输出有界且截断会标明未确认命令完成。当前仅支持 `.git` 位于授权目录内的独立仓库；关联 worktree 的外部 Git 管理目录尚无单独授权接口。没有 Agent commit/push/checkout/merge 工具；产品具备 Git 观察能力，不等于完整 Git 工作流。

依赖镜像可由宿主显式准备。先审查仅含 `package==version` 与 SHA-256 的锁文件，再执行：

```powershell
python -m examples.project_environment --base-image sha256:<已安装完整ID> --requirements requirements.lock --receipt environment.json
```

此命令在准备镜像时联网安装精确哈希依赖，保存基础/结果镜像 ID、锁文件 SHA 和安装清单。它不是模型工具，不执行仓库提供的 Dockerfile；Agent 项目执行仍无网络。锁文件不能包含额外索引、URL、可编辑安装或环境 marker。暂未建立 Node/Cargo 的对应准备流程。

## M6 成本与比较证据

Provider usage 与模型等待时间写入追加日志，界面区分已知 Token、缺失用量和请求数。供应商自报用量不是账单，也不是质量证据。`ModelBudget` 是可注入的宿主预算包装器：请求前预留输入序列化 UTF-8 字节数加协议余量、最多 4096 输出 Token；达到任一请求/Token/估算费用上限即停止，无自动重试。未知耗用保留全额预留并停止；恢复预算日志只恢复记账，不重放任务。当前正式 UI 尚未提供可持久配置的全局费用预算，M6 验收由显式脚本注入；不要把验收预算声称为所有用户默认全局计费控制。

演化预检在生成候选之前处理无检查、捕获材料失败和成本不足。请求估算包含生成、可选审阅、两个任务及历史案例；接入全局 Token 预算时，缺失完整用量或估算超额也停止。估算保守、不保证实际耗用；费用硬上限仍由请求包装器控制。

只复用已经完成的隔离 REFERENCE 执行。键绑定 Harness 源码、Python/系统、工具目录、模型配置版本、任务、Skill、输入、对话、授权及执行策略；再次核对事件、检查与产物字节。普通原任务从不直接代替隔离对照。损坏或条件变化会失效，不把缓存命中当成新一次独立观察。移动/删除任务的冻结重放尚未实现，因此明确停止相应 Skill 比较，不省略这些副作用。

毕业设计页面 `#/research-demo` 只使用已公开冻结记录，无运行数据库读取、实验执行或新评分。旧研究运行入口仍为兼容保留，不再构成新产品开发必须重复的研究流程。
