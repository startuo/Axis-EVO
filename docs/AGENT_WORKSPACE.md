# M4 · Agent-Native Workspace

Axis-Evo **0.1.0 Preview** 默认使用 Chat 与 Work。选择工作区后直接描述目标，Agent 根据任务发现资料和 Skill，调用程序注册的工具，保存文档并继续修订。每次普通文件操作不再要求用户单独批准；操作范围来自用户预先设置的目录与读写策略。

## 启动

在项目根目录使用 Python 3.11+；Windows 凭据管理需要可选 `web` 依赖：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[web]"
.\.venv\Scripts\python.exe -m examples.agent_workspace --data-dir "$env:LOCALAPPDATA\AxisEvo\data" --open-browser
```

完整交付 ZIP 已包含 `web/dist`。源码检出需先在 `web` 目录执行 `npm ci`、`npm run build`（Node 22.12+）。服务器只监听 `127.0.0.1`，默认端口 8765，可用 `--port` 指定。`--api-only` 用于前端开发，`--web-root` 可指定构建目录。

首次打开设置中的「模型连接」配置模型，再添加工作区。工作材料目录与 Agent 状态目录必须分别存放，不能互为父子目录。知识库备份和 Skill 库在「知识与 Skills」中单独授权，只读接入；未连接的目录不会被自动搜索。撤销来源会阻止后续读取与 Skill 使用。

`--network-config` 可接收后端管理员配置的 `credentials` 环境变量引用、`endpoints`、`local_gateways` 和 `provider_routes`。它不接受明文密钥或研究项目配置。网络与模型协议说明见 [AGENT_PROVIDER.md](AGENT_PROVIDER.md)。此启动器不创建研究示例、任务模板或实验数据库。

## 日常协作

- **Chat**：描述目标、附加当前明确选择的 Edge 页面、查看交付物，继续同一会话修订。对话输入与已用 Skill 版本持久保留。
- **Work**：按工作区浏览任务和交付物。交付卡区分当前文件与已保留版本；可预览和下载对应的历史文本。
- **设置**：管理工作区读写范围、资料来源、模型、Skill 改进策略、内置工具、Edge 安装更新以及表达风格。
- **反馈**：说明结果是否有帮助；需要改进时可以补充必含文字、禁含文字或实际标题要求。反馈与本轮执行证据绑定。

内置工具包括列目录、搜索、读取、写入、精确替换、Skill 发现与使用、Edge 正文及快照读取。写入已有文件必须使用已读取的 SHA-256，保存前后版本并独立核对实际字节。工具目前处理 UTF-8 普通文本；父目录需要存在，不运行任意 Shell 或外部 Skill 中的脚本。单文件读取上限 128 KiB，目录扫描最多 2,000 项，单次搜索最多 2 MiB；结果会明确标注截断。

Edge 扩展 **0.2.3 / 协议 2** 会报告自身版本，工作台提供当前目录、更新提示和重连状态。旧协议 2 扩展仍可连接，但显示需更新。重新连接不重放旧操作。Agent 原生工具可观察当前附加页面；有副作用的网页操作继续使用原有精确操作审批，高风险操作交由用户完成。安装步骤见设置的「工具与插件」。

## 运行结构

产品层新增 `agent.sqlite3` 追加式记录、受控工作区服务、工具注册表及原生工具回路。每轮最多 16 次模型请求、48 次工具调用和 600 秒；模型请求使用有墙钟期限的独立进程，取消后迟到响应不得派发工具。Provider 配置版本和网络授权每次重新核对。

模型只提出工具请求。宿主验证工具名、参数、授权来源、目录身份与路径；网页和 Skill 文本不能增加权限。每轮固定来源授权集合；新增或撤销来源会停止当前轮，已发出的模型请求会被取消，迟到响应不得派发操作。文件写入复用原 Core 的安全打开、Tool Intent/Result、验证及 Run 事件，每次修改生成独立 Core 数据库，避免改写旧实验事实。产品持久层和文件记录并非完整 OS 沙箱，也不抵御同一 OS 用户主动修改所有运行状态。

派发意图先于实际操作保存。未经确认的写入会按规范物理路径阻止后续自动重试，包括大小写别名、重叠工作区和完整历史。服务重启把未完成任务保留为 UNKNOWN，不恢复模型请求或副作用。用户仍可继续其它目标；当前没有自动消除未知结果的机制。请求响应丢失时，界面用原请求标识查询事实，不自动新建重复请求。

## Skill 改进

复用现有 `SkillManager`、不可变版本、DERIVED 来源链、修订草案协议及 Core 执行证据。产品 Skill 数据位于独立 `agent-skills.sqlite3`；导入版本是 CANDIDATE，修订版本是 SHADOW，指令不授予工具权限。

负面反馈按工作区策略触发一次周期：

1. 从实际任务、固定 Skill 与反馈生成候选。
2. 可配置另一模型或同模型的独立上下文审查；界面区分两者，审阅只作为建议。
3. 捕获已授权输入并恢复原任务写入前的版本，建立两个隔离工作区。使用同一任务、固定对话输入、模型配置与工具范围，分别实际执行原版和候选；不会重放原网页操作或写入原工作区。
4. 程序重新读取当前交付字节，核对摘要并执行用户指定的文档检查。多次修订只以每个文件的最后版本判断，旧版本仍保留在证据中。
5. AUTO 只在全部要求通过、至少一项改善、没有退步、审查无反对/不确定结论且原授权仍有效时采用候选指令。OBSERVE 保留候选，OFF 只记录反馈。撤销授权或停止策略会中止后续评价与采用。

没有客观检查时不以模型认可代替验证。标题检查使用 Markdown ATX 标题的完整文字，不包含 `#`，编号须一致；代码块中的伪标题不算通过。例如“归档清单”不会匹配“六、归档清单”。采用记录仅表示 **明确文档检查范围内** 的产品偏好版本，不宣称整体语义能力提升。该比较使用开发反馈，不能作为独立 Holdout 或论文实验。旧研究 Gate 要求其封存的评估条件，M4 不伪造旧 Gate/Assessment 或晋升为研究 TRUSTED。

## 当前边界与后续方向

MCP 与 DeepSeek Harness 的协议和架构已经审查；当前使用供应商无关的原生 function calling 与现有受控 Gateway。尚未实现任意 MCP 服务安装、远端工具权限注册或 Harness 联机集成。后续可在同一宿主授权和事实协议下增加适配器。

当前交付以文本文件为主；通用 Office 渲染、任意命令执行、网页跨站自主操作、长期语义质量评价和未知副作用人工核销仍需后续工程。用户真实知识库尚未接入。实际模型、文件、UI 与离线边界测试分别记录在 [TEST_RESULTS.md](TEST_RESULTS.md)。学术研究基线保持 `12c789b187a6bf8332b8d5222d00cc0702d4bdc8`。
