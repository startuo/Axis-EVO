# 下一轮会议纪要研究协议：v3 提案

状态：**PROPOSAL_NOT_AUTHORIZED / NOT_RUN**，2026-10-31。不是第二轮实验的执行授权，不冻结正式 Final Holdout，不启动论文主实验。旧 S1 永久按原字节保留；以下 FB/NF 是未来独立候选指令标识，不是修改旧 S1。

## 可证伪的问题和最小对照

RQ1：持久修订在质量、错误与全成本上，何时比保持 S0 或改进当前答案更值得采用？RQ2：在相同原始轨迹和修订预算下，显式、经核实的真实反馈是否有增量作用？RQ3：对同一候选池，独立质量 Gate 是否减少错误采用，代价和错失机会是多少？

| 条件 | 每个评估案例的行为 | 能排除的部分解释 |
|---|---|---|
| NO_SKILL | 同一任务、组织规则、文件包装器和工具 schema；完全不注入 Skill 指令 | 基础模型已能完成；不能把包装器本身的作用归给 Skill |
| S0 | 固定来源和字节的原 Skill，一次规划 | 保持现状的比较基准 |
| FB_01…06 | 六个独立开发块各从 S0 修订一次；看同样轨迹，加该块真实且经核实的纠错反馈 | 显式反馈带来的候选策略效果 |
| NF_01…06 | 与 FB 成对，同一 S0、开发输入/输出、优化目标、调用预算；不提供评价、错误定位或改进反馈 | 一般提示重写、模型自我诊断与修订计算的作用 |
| DIRECT_REFINE | 复用同案例已经测得的 S0 初稿，额外一次批判及直接重写；不持久修改 Skill，固定采用第二次结果 | 单次答案的额外计算可以达到多少效果 |

不用错误反馈对照：它回答不同问题且增加成本。旧 S1 只作已暴露 Pilot 的历史诊断；不为本研究额外选择有利旧案例。NO_SKILL 保留公共任务说明，不创建一个空 SkillCard 冒充“没有 Skill”。DIRECT 不获得私有参考或人工评估标签；不使用 test Oracle 挑最好答案。第一稿失败时仍保留该失败，第二稿可尝试修复实际失败记录，不能补一次第三稿。

FB/NF 都看原任务与输出，因此 NF 仍可能自行发现错误。RQ2 的 estimand 是**在共同轨迹基础上增加显式可信反馈的效果**，不是所有形式反馈或所有学习的效果。反馈内容、人类成本与信息量本身就是处理的一部分；模型采样和服务端漂移仍可能混杂。

## 实验单位、数据与盲态

- 六个独立开发块，每块两个新会议事件，共 12 个开发案例。每块先用 S0 各运行一次，再形成一次 FB 与一次 NF；不能事后择优重采修订。FB/NF 成对从同一 S0 出发，不继承其他块候选。修订方法的重复单位是这 **6 对**，不是后续 144 个 cell。
- 8 个新事件只用于 Gate 选择；24 个新事件用于下一轮探索性 out-of-sample 评估。24 个案例均覆盖所有条件，构成配对。它们不是正式论文 Final Holdout；使用后登记为已暴露，绝不回收作正式留出。
- 合计 44 个新会议事件/故事簇。由独立资料保管者建立事件来源和语义簇，检查人物关系、业务对象、决策/依赖结构与日期模式；复制模板再改名、替换数额或改日期仍属同一来源簇。跨分区不能共享事件、近重复故事或衍生摘要。共享格式/组织规则仍限制跨域推广，不宣称 44 种完全不同任务类型。
- 旧 Development、Gate、Reuse 14 例，以及旧预备材料、参考、上游示例、公开挑战样本全部进入 exposed inventory。hash/origin/cluster 检查只是必要条件；人类独立检查语义重合并留下摘要和记录身份。当前尚无新研究数据，语义独立性 **PENDING**。
- 输入和私有原子参考先于候选输出固定，参考作者不得查看候选。每条行动、负责人、日期范围、决策状态、关键业务事实、未知值、适用规则都有 ID、来源、适用性和重大性。已承诺行动与必要跟进各有独立清单和分母；不适用项事前登记。
- 评估者不看条件、Skill、反馈、Gate 结果或版本映射。保管者按预定 hash 随机标签保存映射，审阅原件固定后揭盲；操作者不能自称盲态。两名人类独立审定参考与实际产物，争议留 UNKNOWN，裁决以新记录追加，不覆盖原件。LLM 只作可追溯辅助，不填人类字段。

## 配对、随机化与模型控制

开发块内 FB/NF 次序随机；所有部署条件按案例交错。调度使用 `SHA256([20261031, slot_id])` 排序的拓扑序；DIRECT 必须在同案例 S0 返回后才有资格调用。这个种子仅控制本地调度，**没有声称远端可复现采样种子或相同随机噪声**。

`axis_evo.research_comparison.prepare_comparison` 是纯清单与排程准备器：验证 12/8/24、6×2 开发块、固定组织规则、唯一输入/事件/语义簇、排除已暴露来源，产生 488 个带依赖的 slots 与完整 manifest SHA。输入顺序不影响结果。它不读生产版本状态、Gate 或数据库，不调用模型，不接收凭据，也不创建研究授权。重复源字节、同事件改名、跨角色挂开发块等反例实际被拒绝；新的语义簇名不能证明人工检查已做。

旧 Research Runner 的 A/B/C 绑定 v1、候选 receipt、TRUSTED/SHADOW 和首选选择，还限制最多 64 次调用，不能直接表达这些条件。保留它以复现旧研究。将来仅需一个**另行批准的有界文件模拟调用器**消费新 manifest、追加 submission/result 并输出质量审阅材料；本轮没有实现或执行它，不拆成多个旧协议来伪造全局一致性。测量事实、评估标准和选择政策分别有身份，不将探索候选伪造为生产准入版本。

候选可改范围仅为指令文本；输入、组织规则、包装器、评价器、参考、工具集合与结果日志均不可改。当前研究禁止 pytest、run_tests、自定义可执行工具及任意 subprocess。生产权限不由研究比较授予。

所有条件使用同一经批准模型 profile、完整 endpoint、参数和请求 schema。优先沿用受控文件规划能力，具体模型别名及远端 revision 必须重新核对，不能复用已过期网络授权。当前 transport 只发送 `model/messages/n=1/stream=false`，没有可靠 usage、固定 remote revision、temperature/seed/max_tokens 控制。**因此当前不能声称精确 token/FLOP 等预算或锁定远端模型。**

执行前必须决定：采用显式调用/字节预算的探索性控制并接受该限制，或先另行实现和验证受支持的 token cap 与 usage 记账。修订 prompt 的 FB/NF 公共部分完全相同；反馈内容遮蔽，按经核对 tokenizer 控制输入 token 上限。无法核对 tokenizer 时，只报实际请求字节、尝试数、延迟和 UNKNOWN 成本，不宣称严格 token 配平。中途模型或 transport 配置变化停止该批，不混为相同条件。

## 调用与资源上限

| 阶段 | 计算 | 最大本地 adapter attempts |
|---|---|---:|
| 开发 S0 | 6 块 × 2 案例 | 12 |
| 候选修订 | 6 块 × FB/NF 各一次 | 12 |
| Gate 全池测量 | 8 案例 ×（S0 + 12 候选） | 104 |
| 评估第一稿 | 24 案例 ×（NO_SKILL + S0 + 12 候选） | 336 |
| 直接重写 | 24 案例 × 一次额外重写，复用 S0 初稿 | 24 |
| **总上限** | 不包含任何真实人类工作 | **488** |

每个声明 slot 一次、无自动重试。超时/返回未知也消耗 attempt 预算，不能用换 ID 补采。修订失败对应后续候选 slots 标 MISSING_NOT_CREATED，不补造或私选另一版本，按意向处理报告；实际调用数可低于上限。所有条件的评估第一稿均最多 64 KiB 响应、10 Plan steps、120 秒 timeout（待批准配置），每项限制违反均保留失败。单调用被终止不代表远端未完成或未计费。488×120 秒的纯串行调用等待上界为 16小时16分钟，另加本地与人工时间；不声称一定可在此时间内完成。

资金上限提案为 **人民币 100 元，硬上限待所有者批准**。目前模型实际计价、usage、费用控制能力尚未核实，不能据此生成可执行财务批准。若不能实施调用前的保守费用预算和未知消费保留，停止在方案阶段。不得尝试使用本轮会话的授权替代未来 Provider 与数据授权。

人工预算提案上限 80 人时：原子参考 44×两人×10分钟约14.7小时；Gate/评估最终产物最多 104+360=464 份、两人各3分钟约46.4小时；开发反馈与争议预留18.9小时。3分钟是假设，先用已暴露校准材料测量，不动新评估材料。若超支，不看新结果缩减有利子集；停止并为新数据重新登记更小方案。

单候选持久策略的成本报告为 `C_train + C_feedback + C_revision + C_gate + N*C_deploy`，直接重写为 `N*(C_S0 + C_refine)`。同时报告实际共享调用总账与各策略独立运行所需成本；共享 S0 初稿不能在实验总账重复算两次，也不能在单独策略成本中凭空免费。分别呈现调用、token/费用可用性、延迟、人时和质量，不强行合成一个总效用。复用多少次才回本必须由测得成本计算，不能只看单次质量。

## 指标、UNKNOWN 与统计

主要质量终点是**每事件严重事实错误是否出现**（包括关键行动遗漏、虚构责任人/日期、建议变决议、关键数额/状态失真和不确定性被抹去），与**全部预声明事实义务通过的案例比例**，两者分别报告。主观有用性为辅助；组织规范、文件执行与输出缺失另列，不能用总分抵消重大错误。

逐项报告：已承诺行动正确数/固定行动数；必要跟进覆盖；按源行动一对一匹配的 owner/date；所有源行动的最坏情况界限；决策/建议区分；关键事实；无依据新增命题及其重大性；规则适用项；审阅分歧和人工耗时。漏行动的 owner/date 不从整体最坏情况统计中消失，条件正确率必须标明“仅在匹配项中”。0/0 为 NA，未知和缺失保留原固定分母。

分析顺序预先固定：RQ1 报 FB 与 S0、NO_SKILL 的原始策略差，以及仅按 Gate 选择后的策略与 S0、DIRECT 的配对差；RQ2 报六对 FB−NF 的案例均值及全部成败，不只报告最佳候选。报告逐事件和逐修订块分布；不把 6×24 输出当 144 个独立会议。

采用案例簇与修订对的双向重采样（10,000次，分析种子20261101）给出配对差的描述性95%区间，同时列六个修订对和24个事件的原始差异。只有6对修订时 bootstrap 区间不稳定，不以 p<0.05 许诺因果确认。主分析不做事后选端点的显著性筛选。24 个独立事件对差的最坏标准误上界约 `1/sqrt(24)=0.204`（差值范围−1到1），并非足以证明5个百分点收益的精度。样本量由单域、独立重复与488次成本约束决定，是估计与可行性 Pilot；正式样本量需使用新 Pilot 的盲态方差/成本重新事前规划，另取全新数据。

超时、坏 Plan、未创建候选、缺输出均进入意向处理分母；确定的协议失败记失败，结果未知保留 UNKNOWN，报告“未知全错/全对”的界限及失败原因。complete-case 仅为辅助，不替代主结果。原始执行 UNKNOWN 永不因质量审阅改成成功。

## 同一候选池的 Gate 比较

每个开发块的池固定为 `{S0, FB_i, NF_i}`，全部候选在同8例上测量一次，后续重放政策只引用相同事实 SHA，不新增 rollout 或重标结果：

1. KEEP：保持 S0，作为零采用基准。
2. UNGATED：默认选择 FB_i，不看 Gate 质量。
3. EXECUTION：候选满足新试验定义的执行非回归；优先 FB，否则 NF，否则 S0。仅类比旧政策，不冒充重跑历史 `evolution-gate-v1`。
4. QUALITY：候选8例产物有效、全部关键标准通过、无未决/重大无依据新增，且相对 S0 至少修复一个 Gate 案例的关键事实失败、没有其他标准退化；否则保持 S0。两者均满足时选 FB_i，规则事前固定，不根据评估结果改成更好的候选。

QUALITY 对“全持平”返回保留 S0，这是本次研究选择政策；旧 Core 允许持平进入审批的工程语义保留，不应指控为实现错误。没有人类审定的候选不得视为满足 QUALITY。

在24个独立评估案例上测选择政策的严重错误率差、错误采用（选中版本的严重错误率高于 S0）、漏采有益候选、保守保留比例、UNKNOWN/争议率，以及模型/人工/延迟成本。另报相同池中的事后最佳表现作为 regret 描述上界，不用它选择实际版本。采用决策的单位只有6个开发块，错采率不拿144输出作分母。所有选择只用于研究，不晋升或激活生产 Skill。

## 停止、负结果与批准条件

完成全部预声明 slots 或到达任一调用、费用、人时上限即停止；源/参考泄漏、hash 漂移、模型配置改变、评价标准争议未解决则停止新调用并保留已发生尝试。不能因结果不好重写候选、换案例、调阈值或追加轮次。评价器缺陷以新版本与新研究登记解决，不替换旧数据。

允许 NO_SKILL 与 S0 持平；FB 不如 NF；DIRECT 更便宜；质量 Gate 错失收益或人时过高；全部候选被保留策略拒绝；UNKNOWN 太多而无法判断。这些都是结果，不能据此改写成功标准。

执行前必须明确批准：新资料和语义簇清单、人工原子参考与审阅者、两种修订精确 prompt、全部版本/代码/包装器/评价器摘要、完整 slots manifest、Provider 参数与授权期限、488次尝试与费用/人时上限、排除与停止规则。当前这些实际数据与执行配置仍 PENDING，真实模型实验 **NOT_STARTED**；正式论文主实验 **NOT_STARTED**。
