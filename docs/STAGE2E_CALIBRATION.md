## 能力边界与五类反证

| 属性 | 程序能否独立判断 |
|---|---|
| 输入字节、输出集合、非空/UTF-8/NUL | 能，属于产物观察；不证明真实 Runner 执行 |
| 十二节语义结构或排版是否合规 | 不能由现有非空检查证明；需固定规则和审阅 |
| 引用是否逐字存在、offset是否正确 | 能；不能判断引用是否支持结论 |
| owner/date/决策/业务事实正确、重大遗漏 | 不能自动判断；依赖来源有效且审阅正确 |
| 主观可用性、冗余和表达质量 | 需人类或明确标注的 LLM 评价；本轮没有实际人类评分 |
| 证据缺失、已记录意见冲突、标准被指出有争议 | 可保留并阻断确定解释；不能自动发现所有未知问题 |

对 v1 实际执行了如下构造诊断。它们不是自然输出误判率：

1. 所有 PASS 都引用确实存在、却不能支持各事实的“草稿，待审核”：v1/v2 均只能核对位置，仍得到暂定未报告失败。**未修复语义能力边界**。
2. 负责人正确、日期由6日前改为7日前，同时人为给出错误 PASS 审阅：两版仍暂定未报告失败。这证明账本不能自动纠正审阅者。
3. 标准错误要求5日前，来源实际为6日前，忠实产物被审阅为 FAIL：v1 记录重大失败；v2 在标准被明确标为 DISPUTED 后返回 `REFERENCE_DISPUTED`。v2并非自己发现了标准错误。
4. 逐项判断都一致，但全篇审计分别为 CLEAR 和 ISSUES：v1保留两份原件，却不在 `disputes` 中显式登记这种冲突；新 v2 返回 DISPUTED，保留原 v1 报告。
5. 自报 HUMAN 并给出一个64位收据摘要，v1可返回 `HUMAN_SUPPORTED_FOR_DECISION`：这是声明可信度与标签解释的缺口，不能指控实际认证被绕过，因为旧库本来不认证。v2明确写为“声明的人类审阅未报告失败”，仍不建立语义真值或采用授权。

问题归因分别是：语义审阅能力、标准有效性、证据合并逻辑、来源/身份信任假设。不是全部都是程序 Bug。任何总分、排版或高可读性都不抵消重大事实错误。

## 新评价器身份与兼容

新入口为 `axis_evo.minutes_quality_v2.adjudicate_minutes`，身份 `minutes-quality-ledger-v2`。旧 `minutes_quality.py` 和 `minutes-quality-ledger-v1` 原字节保留，旧报告、S0/S1、Oracle、Trial、Gate及UNKNOWN均不覆盖。

v2复用v1的文件、标准、审阅与位置验证，新增单独固定摘要的 context：参考来源时序 `PRE_OUTPUT/POSTHOC/UNKNOWN`、参考有效性 `PENDING/CONFIRMED/DISPUTED`，以及每名审阅者的版本盲态、既有暴露和 independence_group 声明。两个不同 ID 若声明同源组，会显式记关联性；不同组名仍不证明真正独立。

所有完整审计的状态与问题集合进入冲突检查；同一项不同措辞的解释不单独制造冲突。已被指出有争议的标准阻断确定解释。历史v1报告嵌入 `legacy_report` 保留身份，解释新结果应使用v2顶层及其 concerns。所有版本仍 `adoption_authorized=false`、`quality_improved=NOT_INFERRED`。

legacy Core 的 pytest 测试篡改和工作区外副作用缺口仍未修复；当前 Web 禁用该路径，新研究继续限于文件规划/模拟。本轮没有以内容评价为由修改旧 Core 或宣称具备恶意代码隔离。

这些元数据只是可核对声明，不是签名、人类认证、真值或OS访问控制。人类推翻错误标准时，保留旧参考和旧审阅，另建新参考、包和审阅摘要；不得直接修改旧 verdict 来“修复”历史。当前 v2 的人类校准状态仍 PENDING。

## 数据分层与独立性

本地已生成可分发的两阶段材料，原文及历史产物都是旧 Pilot 的虚构组织合成资料，**真实模型产生**与**真实企业材料**不是一回事：

| 用途 | 产物数 | 事件单位 | 身份与限制 |
|---|---:|---:|---|
| 主校准：旧Reuse S0/S1 | 6 | 3 | 保留模型产物原字节；全部已在旧Pilot暴露，操作员知道映射 |
| 主校准：构造挑战 | 6 | 1 | 已暴露的合成例：忠实、漏行动、编owner、错date、建议变决议、关键词填充；预期标签为构造意图，非人类真值 |
| 确认材料：旧Research Gate | 4 | 2 | 事前按case身份hash选择两事件、取双版本，未用于v2规则开发；仍是历史已暴露资料，不是论文未见留出 |

自然历史产物与挑战分别报告，不合并成自然输出准确率。两版同会议不是两个独立事件，重复展示不增加独立样本。当前10份历史产物仅运行独立产物检查并通过，不据此填写事实正确数；自然输出FA/FR仍为null。没有为获得好结果重新筛选旧Pilot案例。

确认材料保留给标准冻结后的独立人类，不用其反馈继续调规则后再声称它是验证集。若修改标准，登记新版本和新用途；正式实验必须另取新事件、来源与语义簇，不能只改文件名、人物或日期。

## 盲态材料与实际审阅程序

`examples.prepare_minutes_calibration` 可从明确授权的catalog生成匿名packet、A/B/C三套不同显示顺序的独立HTML、标准草稿、空名册模板和完整SHA清单。公开源码/Preview只保留工具及合成测试，不包含历史原文、产物、私有标准或身份映射。本地人工材料另行受控分发。

1. 先只发 SOURCE 页：页面文件中物理不含候选输出字节，A/B分别核验来源、义务、分母和重大性。标准不对、来源不支持或有歧义，标 CHANGE/UNKNOWN，并写原因。
2. 收回SOURCE原件，独立解决标准争议，固定参考身份后才发OUTPUT页。参考变更后当前OUTPUT包失效，必须用新目录重新生成；旧包不覆盖。
3. A/B分别阅读全文并逐项给出 PASS/FAIL/MISSING/UNKNOWN、引用和理由，另完成全篇无依据新增/矛盾审计。默认不填任何结论；来源、引用和风格不能代替支持关系。
4. 记录真实既有暴露、能否猜到条件、是否参与过候选生成。只遮蔽版本标签，不保证正文风格不会泄漏身份。作者和本轮Codex不能充当盲态人类。
5. 若要报告审阅者FA/FR，使用独立C作为ADJUDICATOR；C先独立看全部校准样本，再查看A/B意见。仅让C复核分歧会产生核验选择偏差。A/B共识不能用来证明A/B自身准确。只做两人流程可行性时，可先不启用C，但FA/FR继续PENDING。
6. 原始JSON逐份保留。库拒绝同packet/item/reviewer的重复记录自动“取最新”；更正必须追加裁决/版本关系，不能以有利后稿覆盖旧失败。

SOURCE阶段CONFIRM表示参考草稿可接受，CHANGE表示需修改，UNKNOWN表示未决。OUTPUT总体PASS表示关键事实和关键业务规范满足；非关键样式问题单列，不因主观高分掩盖重大错误。未知负责人被补人、明确日期/范围错、承诺条件丢失、建议变决议、关键业务状态失真、关键行动遗漏为重大错误；十二节标题同义表达、纯空行/措辞等通常是MINOR。重大性必须先按来源和用途审定，不能看候选后调整。

缺少来源支持、相对日期基准不明、源记录互相冲突、参考标准有争议、无法决定是否一对一匹配、不同审阅者意见未决，都保留UNKNOWN。没有真实输出的slot记录缺失，不从原分母消失。程序不能为一份从未审过的输出填CLEAR。

## 耗时、误判与分歧测量

HTML通过本机单调时钟分别记录墙钟、活跃毫秒、暂停次数；失焦/隐藏自动暂停，手动暂停不记活跃。它是客户端自记录，不证明人类身份、注意力或真实劳动强度。关闭/未导出就是缺失，不补0。计时并不支持读到一半关页后无损恢复，需重新开始并保留中断说明。

导出字段包含packet、phase、item、reviewer、结论、逐项意见、issues、来源/盲态声明及timing。`validate_session`核对摘要、分母、引用、定时边界。`summarize_sessions`仅在保管者提供已外部核验的名册收据后统计声明的人类记录；自动化/LLM不能填人类耗时。名册区分RATER和ADJUDICATOR，C不混进A/B一致性。

输出保留逐session时间、总体与逐criterion原始配对、关键分歧和暴露情况；结合operator映射分别计算历史模型/构造挑战/确认材料的时间和意见，不能把混合包的总计解释为自然任务性能。当前没有实际人类，耗时、分歧、一致性和FA/FR均为null/PENDING，不能填0%、100%或虚构平均3分钟。

定义：`FA = 预测PASS且独立参考FAIL / 独立参考FAIL数`；`FR = 预测FAIL且独立参考PASS / 独立参考PASS数`。`error_counts`提供完整三分类混淆表，预测UNKNOWN单列为转人工，参考UNKNOWN排除出确定真假类分母但仍在全集；零分母为null。必须同时标明预测来自哪个评价者/政策，以及裁决参考来源、盲态和是否看过预测，不能把同一份审阅同时作预测和真值。

本轮不计算κ或α：没有人类记录，样本也极小。后续先报告逐事件/产物错误数、覆盖/转人工、分歧原件和耗时分布。增加保守策略的代价用“多转人工多少例、增加多少分钟、拒绝多少可用产物”测量，不能把UNKNOWN算一次成功防错。发生标准错误要单列因果归属，避免算成模型生成错误。

统计上，即使若干构造负例零误接受，也不证明自然任务低误率。由独立同分布二项模型的零错误尾概率可推得：若要零错误时95%单侧上界低于5%，需至少59个独立负例；当前同一事件变体不满足这个样本或独立性条件。这只是样本量警示，不是对本项目计算出来的区间。

## 操作入口

从完整源码根目录、安装项目和pytest后：

```powershell
python -m examples.prepare_minutes_calibration prepare --catalog authorized-catalog.json --output new-review-directory
python -m examples.prepare_minutes_calibration analyze --packet new-review-directory/operator/output-packet.json --sessions returned-json --output new-summary.json
```

没有已核实名册时分析保留PENDING；有实际人类数据后才显式增加 `--roster confirmed-roster.json`。空模板 `{}` 不代表核验完成。重复输出目录或摘要文件拒绝覆盖。误差计数API见 `axis_evo.review_calibration.error_counts`，须先按operator人口清单分层并建立独立裁决标签；库不会自动发明参考答案。

## 研究规模与下一阶段准入

**不建议现在批准488次。** 将v3保留作历史提案，新的v4先以96次上限检验流程、方向和成本：3对独立FB/NF、6开发/4Gate/8评估新事件，仅保留S0/FB/NF；每事件共享一次S0测量，Gate不同政策重放同池事实。实际排程准备器为 `research_feasibility.prepare_feasibility`，不含网络调用或生产资格变更。

| 阶段 | 上限 |
|---|---:|
| 开发S0：3块×2新事件 | 6 |
| 同轨迹FB/NF各一次修订 | 6 |
| Gate：4例×(S0+6候选) | 28 |
| 评估：8例×(S0+6候选) | 56 |
| **合计** | **96** |

删除NO_SKILL：它回答基础模型是否需要Skill，超出本次优先检验的“持久修订相对固定Skill”问题。删除DIRECT：先不回答持久投入和额外单次推理谁更划算；不得因删去该组而宣称排除了推理预算替代解释。FB/NF同轨迹、同调用上限，仅显式反馈差异；实际token、信息量和远端revision仍需记录局限。

96比488减少约80.3%尝试上限，但研究效力也更低。独立单位是8个评估事件、3对修订、3次候选池采用决定，不是56输出或96调用。3对即使方向一致也不足以建立稳定因果收益；只报原始配对差、负例和成本，不许诺显著性。不能在4个Gate事件上调政策，再用相同事件声称泛化。

人工上限不再填80小时：18事件×2参考=36次；90个潜在任务输出×2审阅=180次；6候选人工检查=6次，共222个计划session，另加反馈与独立裁决。`36*t_ref + 180*t_output + 6*t_candidate + t_feedback + t_adjudication` 需要真实校准时间才能换算人时。C若全量核验会另增最多108个参考/输出session；应按实际研究目的预算，不能藏在人时预留。当前人时及人民币上限均未批准，不用100元作为费用控制证据。

执行准入的最少条件：

1. 完成SOURCE审定及至少两名独立人类的盲态小样本审阅；若要FA/FR结论，增加独立裁决，并对保留确认材料只做一次冻结后核验。重大争议不靠投票或调阈值消除。
2. 得到实际耗时/转人工成本及错误模式，明确允许的保守决策、人工覆盖和停止预算。校准不能支持自动评分时，可以选择人类主评的探索性研究，不能继续宣称自动评价已可信。
3. 准备18个真正新事件、参考与语义簇审定；排除所有旧Pilot、预备、公开挑战及本校准/确认材料。当前只有排程工程夹具，没有这些新研究数据。
4. 完成精确Provider/源码/请求/slot/提交记录/费用边界批准及最小有界执行接线验证。旧Runner绑定A/B/C且64次上限，不能直接冒充能消费v4全局清单。本轮不为尚未确定的评价和人力预算建设新执行平台。

达到全部条件后才申请一个96次以内、无自动重试的单轮可行性研究。超时、坏输出、未生成候选均保留；完成一轮后若FB/NF与S0持续持平，停止扩轮而非继续优化旧S1。任何扩样或正式论文实验必须另行预注册、独立数据、样本量/方差依据、费用批准和执行验证；不会自动进入488次或正式Holdout。

## 一手依据及适用范围

[RSIHub v1](https://arxiv.org/html/2610.32253v1)提供测量与候选选择分离的边界；受保护的评价器仍可能无效，本阶段没有复现其收益。[Rethinking Self-Evolving Agent Skills v1](https://arxiv.org/html/2608.02636v1)支持记录反馈消融、稀疏改善和推理预算对照；其模型/任务结论不外推到会议纪要，删DIRECT后保留相应未排除解释。

[MT-Bench的LLM评审研究](https://arxiv.org/abs/2306.05685)指出位置、篇幅、自我偏好等偏差，促使本方案遮蔽标签、变换顺序并记录既有暴露；不引用该文的人类一致率作为本项目指标。[Artstein与Poesio](https://aclanthology.org/J08-4004/)说明一致性系数有任务和分布假设，因此本阶段先保留原始配对及未知，不制造一个一致性总分。[NIST二项区间说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)用于约束小样本和零错误解释；上述59例是明示假设下的数学推导。

本地项目卡及Harness/Loop分层笔记只用于定位，共享LLM盲点不能因换上下文就消失。知识库只读，未更新笔记、未把行业概念当原始学术证据。新增工具都服务于校准、来源、成本与协议身份；没有新MCP、Multi-Agent、RAG、前端产品系统或沙箱重构。
