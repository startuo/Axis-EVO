# Pilot Organization A — Internal Project Operations

版本：fictional-office-policy-v1。来源：SYNTHETIC_OFFICE_SCENARIO。这是虚构组织的试验规则，不是实际企业制度或部署记录。

1. 输出中文 Markdown 纪要，保留上游十二节的语义结构；简洁表达，不靠扩充篇幅补足证据。
2. 区分“已批准决策”“提出但未批准的建议”和“尚待解决的问题”。讨论、倾向、估计或沉默不视为批准。
3. 负责人仅由明确分工或明确接受的任务确定。未指派写 TBD/Unknown，说明向谁或通过何流程确认；不得按发言人、职务或部门自行补人。
4. 日期以明确承诺为准；相对日期只在会议日期已知且含义明确时换算，并保留原说法。冲突日期同时记录为待确认，不能擅选其一；“尽快”保留为时间范围，不编造具体日。
5. 行动项区分已承诺任务与待分配工作；仅记录原文支持的验收条件，无条件时标待补充，不发明指标。
6. 跨部门依赖明确记录上游提供物、下游受影响事项与已说明的状态，不把依赖未满足写成项目已完成。
7. 原文明确为高优先级的 blocker 单独突出；没有依据不自行升级风险级别，也不因积极表态宣布解除阻塞。
8. 重要决策、任务和 blocker 应附来源段落编号，例如 [S03]；引用只证明出处，不能替代对原文的忠实表述。
9. 缺失或不确定元数据保留 TBD/Unknown，写明补充途径。只能使用预收集 Intake 的实际答复，不推测未提供的日期、到场者或审核结论。
10. 不新增原文没有的人事、财务、客户或运营断言。本轮全部人名、团队、项目和记录为合成资料；不把它们当真实个人信息或公司成果。
11. 本轮只生成供复核的本地草稿 minutes.md，不发布、发信、建 ticket 或修改任何外部系统。
12. 文件成功生成、Core Acceptance 和 Gate eligible 只按各自实际语义报告；内容质量与版本改进必须另列审阅证据和分母，缺失评价保持 PENDING。
