## M6 失败核对与修复

- 首次真实任务的替换锚点来自正确源摘要，模型参数为 LF，源文件为 CRLF。M6 已允许统一 CRLF 文件的等价匹配。M6.1 同时修复唯一锚点本已匹配时引入 LF 的问题，并允许在摘要固定的同一版本按行编辑，拒绝时给出匹配数或可用行范围。
- M6 续跑 9 次成功读取中有 5 次与此前读取的文件摘要和范围完全相同。24 KiB 试验版本在连续回合压缩材料，出现重复读取后仍无写入。M6.1 先去重相同读结果，再保留最近的活动源码范围，优先压缩搜索和列表。原任务要求及完整工具事实仍保留。
- 按原工具回执重建的对比中，M6.1 续跑上下文共 199,571 字节，M6 最终 48 KiB 策略为 217,911 字节。同样对比的首次任务中，M6.1 为 443,506 字节，M6 最终策略为 436,586 字节。重建使用统一工具目录和固定原请求，只反映投影体积，无法反推 Provider Token 或完成率。
- 用量日志保存上下文摘要和字节数，分开记录已发请求与宿主拦截。预算达到实际约束和预留超出剩余量使用不同原因。固定检查机制、权限和未知副作用围栏沿用现有 Runtime。
- 本地实跑确认另一个故障路径。`python-slugify` 失败后的请求含两个固定测试的完整 stdout，体积 80,317 字节。Ollama 报告在该轮截断输入。Runtime 现在保留检查结论、退出码、输出首尾和原文摘要，减少送进模型的重复测试输出。捕获该请求后用相同材料重放，体积从 80,317 降至 58,408 字节。
- Tomli-W 的项目概览夹带大量测试 fixture 元数据。对模型展示受限的路径清单，保留项目配置、测试入口及原始文件计数。两次捕获请求分别从 49,047 和 65,445 字节降至 17,225 和 33,623 字节。完整回执仍保留在 Runtime 日志中。这些差异来自确定性投影重放，不能换算成同模型的端到端 Token 或成本收益。

The original validation matrix exercised Python3.12 only; disclosing deprecation debt did not verify cross-version behavior. This was our boundary-ordering and compatibility-coverage omission. The failing cases remained fail-closed; they did not establish unsafe execution.
